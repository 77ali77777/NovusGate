# P2d-3 Named DTOs for Every Request and Response Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace every handler-local anonymous request struct and every `map[string]…` JSON response with a named Go DTO, **without changing a single byte of meaning on the wire**. The OpenAPI document then describes real types instead of `{"type":"object"}`, and P5 can generate a typed client from it.

**Architecture:** Three gates per domain, in this order:
1. **Freeze.** Every response shape that will change representation is first frozen in contract snapshots (Task 1). This covers host-dependent paths with stubbed commands, and the firewall through the engine test server.
2. **Describe.** `docOps` switches from `freeform{}` to DTO types before the handlers change. `assertMatchesSpec` then validates today's map responses against the new DTO schemas, which proves each DTO describes the current wire: required keys always present, conditional keys optional, no extra keys.
3. **Convert.** Handlers switch from maps to the DTOs. The unchanged snapshots prove the wire did not move.

Conditional keys use pointer fields with `omitempty` wherever a present value can be zero, `false`, `""` or empty.

**Tech Stack:** Go 1.23, gorilla/mux, PostgreSQL 16 (tests).

**Spec:**
- `docs/superpowers/specs/2026-10-13-p2-backend-core-design.md` §5 (P2d-3) and P2d-2's out-of-scope note ("named DTOs for the anonymous request structs and freeform responses").
- Master spec `docs/superpowers/specs/2026-10-13-novusgate-rebuild-design.md` §3.1 (API contract frozen) and §5 (P5 needs OpenAPI).

## Global Constraints

- **No API behaviour change.** Every existing contract snapshot stays byte-identical through Tasks 2–5. A snapshot diff is a defect, not something to update.
- **Scope ruling: the service layer is NOT part of P2d-3.** P2's acceptance criteria (master spec §5) are snapshots green, reconciler shadow with zero unexplained drift, and expiry working with the panel closed. Moving business logic out of handlers is a large refactor with no user-visible value and real regression risk. It is re-planned when a later phase needs it (P6 or a later P2 follow-up). The ledger records this as a ruling.
- **No new Go modules or npm packages.**
- **`errorResponse`/`errorWithCode` are untouched.** `GET /debug/wireguard/{id}`'s 404 body `{"network_id","error"}` keeps its current non-standard shape (P2d-2 deferred minor M-3); it gets its own DTO.
- **`openapi.go`'s own `map[string]any` document stays a map.**
- **Environment:**
  - Go runs only in Docker: `bash server/scripts/test-with-postgres.sh`.
  - Snapshots are updated with `bash server/scripts/update-contracts.sh`, in Task 1 only, plus the golden OpenAPI in Tasks 2–5.
  - The WSL shim expands `$`/`|`, so logic goes in script files.
- Commits carry no `Co-Authored-By`/"Claude"/"Anthropic"/"AI generated" lines. Comments in English, docs in Azerbaijani with full diacritics.

## Review Focus

1. **A conditional key whose present value is zero, `false`, `""` or `[]`.** Examples: `banned_count: 0`, `firewall.ready: false`, `egress_interface: ""`, `banned_ips: []`.
   - Expected: still present after conversion.
   - Pinned by Task 1 snapshots, which include such values (jail with 0 failed, nft engine ready false, ...), and the unchanged-snapshot gate.
2. **A key that was `null` and must stay `null`, never `[]`.** Examples: `pending: null` in v2 state/propose, `last_run: null`.
   - Expected: still `null`.
   - Pinned by the `fw_v2_state` and `health` snapshots.
3. **Mutually exclusive key groups.** Examples: fail2ban logs `error` vs `count`; v2 state `host_error` vs `ssh_ports`/`egress_interface`; debug `wg_error` vs `wg_peers`.
   - Expected: the same group appears in each case.
   - Pinned by Task 1 cases for both branches where they are reachable with stubs.
4. **`GET /system/info` reads `/proc`, so its values vary.**
   - Expected: its key set and JSON types stay the same.
   - Pinned by Task 1 `TestSystemInfoShape`, which checks key → JSON type.
5. **Request DTOs.**
   - Expected: today's JSON field names and pointer-ness are kept (`expires_at` stays a `*string` in node updates), so clients' bodies decode exactly as before.
   - Pinned by the existing handler tests (`TestUpdateNodeValidatesInput`, contract login/password/node cases), which run unchanged.

// TestSystemInfoShape pins /system/info's keys and JSON types; its values
// come from /proc and vary between machines.
func TestSystemInfoShape(t *testing.T) {
	s, _, stub := newContractServer(t)
	stub.out["df -B1 /"] = "Filesystem 1B-blocks Used Available Use% Mounted on\n/dev/sda1 1000 400 600 40% /\n"
	rec := callAs(t, s, "GET", "/api/v1/system/info", "", true)
	var body map[string]any
	if err := json.Unmarshal(rec.Body.Bytes(), &body); err != nil {
		t.Fatal(err)
	}
	always := map[string]string{"cpu_cores": "number", "hostname": "string", "memory_total": "number", "memory_free": "number",
		"memory_available": "number", "memory_used": "number", "memory_buffers": "number", "memory_cached": "number",
		"disk_total": "number", "disk_used": "number", "disk_free": "number"}
	optional := map[string]string{"cpu_model": "string", "load_1m": "string", "load_5m": "string", "load_15m": "string", "uptime_seconds": "number"}
	kind := func(v any) string {
		switch v.(type) {
		case string:
			return "string"
		case float64:
			return "number"
		}
		return "other"
	}
	for k, want := range always {
		if v, ok := body[k]; !ok || kind(v) != want {
			t.Errorf("%s = %v (%s), want a %s", k, v, kind(v), want)
		}
	}
	for k, v := range body {
		want, ok := always[k]
		if !ok {
			want, ok = optional[k]
		}
		if !ok || kind(v) != want {
			t.Errorf("unexpected key or type %s = %v", k, v)
		}
	}
}

package rest

import (
	"time"

	"github.com/novusgate/novusgate/internal/shared/models"
)

// Request DTOs. Field names, JSON tags and pointer-ness are exactly the
// anonymous structs the handlers decoded before, so request bodies decode
// the same way.

type LoginRequest struct {
	Username string `json:"username"`
	Password string `json:"password"`
}

type UpdatePasswordRequest struct {
	Username    string `json:"username"`
	OldPassword string `json:"oldPassword"`
	NewPassword string `json:"newPassword"`
}

type CreateUserRequest struct {
	Username string `json:"username"`
	Password string `json:"password"`
}

type UpdateNodeRequest struct {
	Name      *string          `json:"name"`
	ExpiresAt *string          `json:"expires_at"` // RFC 3339, "" removes the expiry
	Status    *string          `json:"status"`
	NodeInfo  *models.NodeInfo `json:"node_info"`
}

type NodeCheckInRequest struct {
	NodeInfo *models.NodeInfo  `json:"node_info"`
	Labels   map[string]string `json:"labels"`
}

type CreateServerRequest struct {
	Name      string            `json:"name"`
	Labels    map[string]string `json:"labels"`
	ExpiresAt *time.Time        `json:"expires_at,omitempty"`
}

type Fail2BanJailIPRequest struct {
	Jail string `json:"jail"`
	IP   string `json:"ip"`
}

type Fail2BanBanRequest struct {
	Jail      string `json:"jail"`
	IP        string `json:"ip"`
	Permanent bool   `json:"permanent"`
}

type Fail2BanJailSettingsRequest struct {
	Jail     string `json:"jail"`
	Bantime  string `json:"bantime"`
	Maxretry string `json:"maxretry"`
	Findtime string `json:"findtime"`
}

type Fail2BanWhitelistRequest struct {
	Jail   string `json:"jail"`
	Action string `json:"action"` // add | remove
	IP     string `json:"ip"`
}

type Fail2BanIPRequest struct {
	IP string `json:"ip"`
}

type Fail2BanJailControlRequest struct {
	Jail   string `json:"jail"`
	Action string `json:"action"` // start | stop
}
